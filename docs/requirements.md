# 要件定義

## 1. サービス概要

ワンルーム投資物件を提案されたユーザーが、提示された価格が適正かどうかを自分で確認できるサービス。
物件情報を入力すると、クライアント提供の収益率データに基づいて
**割安 / 相場通り / 割高** の 3 段階で判定し、相場価格帯と提示価格との差額を提示する。

内部では収益率（利回り）を用いるが、**ユーザー画面には利回りを主要な診断結果として表示しない**。

## 2. ユーザーフロー（確定）

```
LP
 └ [無料で相場を確認してみる]
    └ 物件情報入力（所在地 → 建物 → 収支）
       └ [この物件の相場を確認してみる]
          └ 会員登録 / ログイン案内   ← ここまで未ログインで到達できること
             └ 会員登録 or ログイン
                └ 入力済み物件情報を引き継いで診断
                   └ 診断結果
                      └ 無料診断の利用状態を保存
                         └ 2 回目以降は有料診断へ誘導
                            └ Stripe 決済
                               └ 決済状態をサーバーで確認
                                  └ 有料診断が利用可能
```

会員登録を最初に要求しない。入力途中の値はブラウザに一時保存し、登録・ログイン後に自動で復元する。

## 3. 機能要件

### 3.1 物件情報入力

指示書 §3 の 7 項目を扱う。

| # | 項目 | 型 | 単位 | 必須 |
| --- | --- | --- | --- | --- |
| 1 | 物件価格 | 整数 | 万円 | ○ |
| 2 | 築年数 | 整数 | 年 | ○ |
| 3 | 最寄り駅 | 文字列（マスタ補完） | — | ○ |
| 4 | 駅徒歩分数 | 整数 | 分 | ○ |
| 5 | 月額賃料 | 整数 | 円 | ○ |
| 6 | 管理費 | 整数 | 円 | ○ |
| 7 | 修繕積立金 | 整数 | 円 | ○ |

加えて **所在地（都道府県・市区町村）** を入力する（`docs/analysis.md` ASSUMPTION-1）。
駅名が収益率データに存在しない場合の市区町村フォールバックと、シート特定に必須のため。

### 3.2 バリデーション

フロントエンドとサーバーの両方で同一のスキーマを用いて検証する。サーバー側の検証を正とする。

| 条件 | 扱い |
| --- | --- |
| 数値項目が空 | エラー「入力してください」 |
| 数値以外の文字 | エラー「半角数字で入力してください」 |
| 負の値 | エラー「0 以上で入力してください」 |
| 物件価格 0 | エラー（0 除算を防ぐ） |
| 物件価格 > 100,000 万円 | エラー「金額をご確認ください」 |
| 築年数 < 0 または > 120 | エラー |
| 駅徒歩 < 0 または > 120 | エラー |
| 月額賃料 0 または > 10,000,000 円 | エラー |
| 管理費・修繕積立金 < 0 または > 1,000,000 円 | エラー |
| 管理費 + 修繕積立金 ≥ 月額賃料 | エラー「実質収入が 0 以下になります」 |
| 都道府県が一覧外 | エラー |

エラーメッセージはすべて日本語で、何をどう直せばよいかが分かる文言にする。

### 3.3 診断

`docs/diagnosis-logic.md` に定義する。

### 3.4 会員

- メールアドレス＋パスワードで登録。表示名は任意。
- パスワードは 8 文字以上。bcrypt でハッシュ化して保存。
- ログイン / ログアウト。
- 自分以外の診断・決済情報には一切アクセスできない。

### 3.5 利用回数の制御

- 初回 1 回は無料。`User.freeDiagnosisUsedAt` で管理する。
- 2 回目以降は有料。**サーバー側でのみ判定する**（フロントのフラグは信用しない）。
- 有料枠は Stripe Webhook、またはローカル専用の Mock Payment でのみ付与する。
  Mock は `PAYMENT_PROVIDER=mock` かつ localhost に限る。本番では無効。

### 3.6 決済

- 本番想定は Stripe Checkout。Secret Key はサーバー側の環境変数のみ。
- 料金・Price ID は未確定（`docs/open-questions.md`）。確定するまで本番仕様として埋め込まない。
- ローカル確認用に `PAYMENT_PROVIDER=mock` を用意する。画面に TEST ONLY と明示する。
- Webhook は署名検証を必須とする。
- 都度課金とサブスクリプションの両方の状態を保持できる構造にする。
  サブスクは `active` / `trialing` を利用可、`canceled` / `past_due` / `incomplete` / `unpaid` は利用不可とする。
- 決済完了画面の表示だけでは権限を与えない。

### 3.7 マイページ

アカウント情報、無料診断の利用状況、有料利用枠の残数、決済状態、診断履歴の閲覧。

### 3.8 管理画面

管理者（`User.role = ADMIN`）のみ。ユーザー一覧、診断一覧、決済一覧、
収益率データ（シート／エリア／駅／市区町村／レンジ）の閲覧、データ検証結果の確認。
高度な分析ダッシュボードは作らない。

## 4. 非機能要件

| 分類 | 要件 |
| --- | --- |
| レスポンシブ | 360px〜。横スクロールを発生させない。タップ領域 44px 以上 |
| アクセシビリティ | label と input の関連付け、キーボード操作、フォーカス可視、コントラスト比 4.5:1 以上、エラーの `aria-describedby` / `role="alert"` |
| セキュリティ | `docs/architecture.md` §セキュリティ を参照 |
| 拡張性 | 収益率データの変更をコード修正なしで反映できること |
| 表現 | 誇張・煽り表現を使わない。算出根拠と免責を明示する |

## 5. スコープ外（MVP では作らない）

物件検索、複数物件の比較、PDF 出力、メール配信、SNS ログイン、パスワードリセットメール送信基盤、
分析ダッシュボード、収益率データの管理画面からの編集 UI（閲覧のみ）。
