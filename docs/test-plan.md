# テスト計画

「動いているように見える」ではなく、入力から結果・課金制御まで成立することを確認します。
診断結果に影響する仕様は、クライアント提供データと突き合わせて検証します。

---

## 1. 層

| 層 | 場所 | 実行 |
| --- | --- | --- |
| 診断エンジン | `engine/tests/` | `cd engine && .venv\Scripts\python.exe -m pytest` |
| Web 単体 | `web/tests/` | `cd web && npm test` |
| E2E | `web/e2e/` | DB とエンジン起動後、`cd web && npm run e2e` |

E2E は Playwright、ワーカー 1 です。開発用 DB が同時接続に弱いためです。
ブラウザは本機の Chrome（`E2E_CHANNEL=chrome`）を使います。

## 2. 診断エンジン（必須）

### 計算例

指示書の例: 賃料 90,000 − 管理費 7,820 − 修繕積立金 4,260 = 月間 77,920、年間 935,040。
横浜駅・築 7 年・2,670 万円は内部収益率 約 3.50%。エリア①のレンジ 3.20%〜3.39% より高いので **割安**。
相場価格は 2,758万円〜2,922万円。

### エリア優先（駅 → 市区町村。逆にしない）

| 入力 | 期待 |
| --- | --- |
| 横浜駅 / 横浜市 | ①（駅） |
| 未登録駅 / 横浜市 | ③（市） |
| 武蔵小杉駅 / 川崎市 | ②（駅） |
| 未登録駅 / 川崎市 | ③（市） |
| 未登録駅 / 未登録市 | シートの「それ以外」 |

「横浜」と「横浜駅」は同じ。「横浜」と「横浜市」は別。

### 境界値

横浜駅・築 7 年のレンジは 3.20%〜3.39%。年間実質収入を 935,040 円に固定し、価格だけ動かします。

| 価格 | 収益率の目安 | 判定 |
| --- | --- | --- |
| 2,931 万円 | 3.19% | 割高 |
| 2,922 万円 | 3.20% | 相場通り |
| 2,758 万円 | 3.39% | 相場通り |
| 2,751 万円 | 3.40% | 割安 |

判定はセルの `[low, high]` から導きます。全エリア共通の固定閾値は使いません。

### その他

- 築 0〜1 → `0~1`、築 35 以上 → `35以上`
- 不正セル（東京④・築35以上 `4.70%-4.49%`）は計算せず `DATA_UNAVAILABLE`
- 徒歩分数は計算に使わない（データに区分が無い）
- 実質収入が 0 円以下は拒否

## 3. Web 単体

- 入力バリデーション: 空欄、文字列、マイナス、0、過大、小数、全角数字・カンマの正規化
- 表示: 万円帯、差額文言、「0万円高い」と書かない、見出しに利回りを含めない
- `?next=` の外部 URL 拒否
- 利用権限: 初回無料、使い切り、残数、ACTIVE/TRIALING のみ有効
- エンジンクライアント: 公開結果と内部値の分離、未登録データの案内
- Stripe Webhook: 署名必須、決済成立で残数付与、未払いは付与しない、重複イベント、失敗時 500、返金・期限切れ

## 4. E2E

通し:

LP → 「無料で相場を確認してみる」→ 7 項目＋所在地入力 → 「この物件の相場を確認してみる」
→ 会員登録 → 診断結果 → 再読み込みしても残る → 2 回目は有料案内（決済未設定なら準備中）

加えて:

- 入力前に会員登録を求めない
- 入力途中の再読み込みで下書きが残る
- 結果画面に利回り・内部コードを出さない
- 空欄・不正値の日本語エラー
- ログアウト／ログイン
- 他人の診断 ID は 404
- 未ログインで診断 API は 401
- 一般ユーザーに管理画面は 404
- スマホ幅で横スクロールしない
- ラベルと入力欄の対応

- Stripe の実カード決済は Price ID 未確定のため E2E では回しません。
  ローカルでは Mock Payment（`PAYMENT_PROVIDER=mock`）で
  決済 → payment PAID → 残数付与 → 有料診断まで確認します。
  Webhook は単体で署名検証まで確認します。
