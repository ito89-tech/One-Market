# 診断ロジック仕様

すべての根拠はクライアント提供の `利回りシート .ods`（→ `data/yield-master.json`）です。
シートに無い値を推測して補うことはしません。

実装は `engine/app/diagnosis.py` に責務ごとの純粋関数として置き、UI からは分離します。

---

## 1. 処理の流れ

```
入力
 ├─ 所在地（都道府県・市区町村）
 ├─ 最寄り駅・駅徒歩分数
 ├─ 築年数
 └─ 物件価格・月額賃料・管理費・修繕積立金
      │
      ▼
① resolve_sheet()          都道府県 → 参照するシートを決める
② resolve_area()           駅名 → 市区町村 の順でエリア区分を決める
③ resolve_age_bracket()    築年数 → 築年数区分の行を決める
④ find_yield_rate()        ②③ の交点から収益率レンジ [low, high] を取得
⑤ calculate_net_income()   月間実質収入
⑥ calculate_annual_income() 年間実質収入
⑦ calculate_yield()        内部収益率（％）
⑧ calculate_market_price() 相場価格帯
⑨ judge_price()            割安 / 相場通り / 割高
      │
      ▼
出力（ユーザー向け）＋ 内部情報（ユーザーには返さない）
```

---

## 2. ① シートの決定 `resolve_sheet()`

都道府県名から参照シートを選びます。

| 都道府県 | シート |
| --- | --- |
| 東京都・埼玉県・神奈川県・千葉県 | 東京・埼玉・神奈川・千葉 |
| 大阪府・京都府・兵庫県 | 大阪・京都・兵庫 |
| 福岡県 | 福岡 |
| 愛知県 | 愛知・その他 |
| **上記以外のすべて** | 愛知・その他（`isFallback: true`） |

最後の行はシート上の注記
「広島や岐阜など利回りシートに記載されている以外の都道府県や市町村はすべてこの利回りで統一してください」
に従ったものです。

---

## 3. ② エリア判定 `resolve_area()` — 最重要

**照合順序を絶対に逆にしないこと。**

```
1. 駅名で一致するか  → 一致したエリアを採用して終了
2. 市区町村で一致するか
     2-a. 「区」で一致するか   → 採用して終了
     2-b. 「市」で一致するか   → 採用して終了
     2-c. 「町 / 村」で一致するか → 採用して終了
3. シートの「それ以外」区分を採用
```

### 根拠となるデータ

| 入力 | 結果 | 理由 |
| --- | --- | --- |
| 横浜駅 | ① | 東京シート ① の JR 列に「横浜」 |
| 横浜市（駅が未登録の場合） | ③ | 東京シート ③ に「横浜市」 |
| 武蔵小杉駅 | ② | 東京シート ② の駅列に「武蔵小杉」 |
| 川崎駅 | ② | 東京シート ② の駅列に「川崎」 |
| 川崎市（駅が未登録の場合） | ③ | 東京シート ③ に「川崎市」 |

**「横浜市だから ③」としてはいけない。「横浜駅」は ① です。**

### 2-a と 2-b を分ける理由

大阪シートは ② に `大阪市`、③ に `淀川区`・`東淀川区`・`都島区`・`東成区` を持ちます。
これらは大阪市の行政区なので、市を先に照合すると ③ の 4 件に到達できなくなります。
より狭い行政単位を優先することでのみデータが成立します。

### 駅名の正規化ルール `station_key()`

| 処理 | 例 |
| --- | --- |
| NFKC 正規化 | `ＪＲ` → `JR` |
| 空白の除去（全角含む） | `武蔵 小杉` → `武蔵小杉` |
| **末尾の「駅」1 文字のみ除去** | `横浜駅` → `横浜`、シート側の `天満駅` → `天満` |
| 中黒の除去 | `元町・中華街` → `元町中華街` |
| `ヶ`/`ヵ` → `ケ` | `阿佐ヶ谷` → `阿佐ケ谷` |

**やってはいけないこと**

- 市区町村の接尾辞（市 / 区 / 町 / 村）を除去すること。
  `横浜市` は決して `横浜` にならず、駅名「横浜」と一致しません。
- 部分一致・前方一致・あいまい検索。別駅への誤判定を招くため **完全一致のみ** とします。
  表記ゆれは上記の正規化と、入力欄でのマスタ候補提示で吸収します。

### 市区町村の正規化ルール `locality_key()`

NFKC 正規化と空白除去のみ。接尾辞は保持します。

---

## 4. ③ 築年数区分 `resolve_age_bracket()`

シートの行は `0~1` / `2` / `3` / … / `34` / `35以上` です。

| 築年数 | 採用する行 |
| --- | --- |
| 0, 1 | `0~1` |
| 2〜34 | 同じ数字の行 |
| 35 以上 | `35以上` |

`ageMin ≤ 築年数 ≤ ageMax`（`ageMax` が `null` なら上限なし）で判定します。

---

## 5. ④ 収益率の取得 `find_yield_rate()`

シート × 築年数区分 × エリア区分 の交点にあるレンジを取得します。

- セルが存在しない、または `valid: false`（下限＞上限などの不正値）の場合は
  **推測で補わず** `DATA_UNAVAILABLE` を返します。
- 現在 `valid: false` は 1 件のみ:
  東京シート / ④エリア / 築 35 年以上 = `4.70%-4.49%`（`docs/analysis.md` BLOCKER-1）。

---

## 6. ⑤〜⑦ 収支計算

```
月間実質収入 = 月額賃料 − 管理費 − 修繕積立金
年間実質収入 = 月間実質収入 × 12
収益率(%)    = 年間実質収入 ÷ 物件価格 × 100
```

指示書 §4 の例で検証:

```
90,000 − 7,820 − 4,260            = 77,920 円/月
77,920 × 12                       = 935,040 円/年
935,040 ÷ 26,700,000 × 100        = 3.5020...%  ≒ 3.50%
```

- 計算は `Decimal` で行い、途中で丸めません。
- 月間実質収入が 0 以下になる入力は、計算前にバリデーションで弾きます。

---

## 7. ⑧ 相場価格帯 `calculate_market_price()`

```
相場価格の下限 = 年間実質収入 ÷ (high / 100)
相場価格の上限 = 年間実質収入 ÷ (low  / 100)
```

収益率が高いほど価格は安くなるため、**high が下限価格、low が上限価格** になります。
この逆関係を取り違えないこと。

表示は 1 万円未満を切り捨てて万円単位にします。
丸めは表示のためだけに行い、判定には使いません。内部計算は円のままです。

---

## 8. ⑨ 判定 `judge_price()`

エリア × 築年数のレンジ `[low, high]` に対して:

| 条件 | 判定 | ユーザー向け表現 |
| --- | --- | --- |
| 収益率 < low | `OVERPRICED` | 割高 |
| low ≤ 収益率 ≤ high | `FAIR` | 相場通り |
| 収益率 > high | `UNDERPRICED` | 割安 |

指示書 §11 の「3.19% 以下 = 割高 / 3.20〜3.39% = 相場通り / 3.40% 以上 = 割安」は、
`[low, high] = [3.20, 3.39]`（東京シート ①エリア・築 6〜9 年）を代入した場合と完全に一致します。
閾値はハードコードせず、常にデータのレンジから導きます。

### 境界値の扱い（必須テスト項目）

`[low, high] = [3.20, 3.39]` のとき:

| 収益率 | 判定 |
| --- | --- |
| 3.19% | 割高 |
| 3.20% | 相場通り（境界を含む） |
| 3.39% | 相場通り（境界を含む） |
| 3.40% | 割安 |

浮動小数点の誤差で境界がずれないよう、比較は `Decimal` で小数第 2 位に量子化してから行います。

### 判定と価格帯の整合

```
収益率 > high  ⇔  物件価格 < 相場下限   （割安）
収益率 < low   ⇔  物件価格 > 相場上限   （割高）
```

が恒等的に成り立つため、判定と価格帯が矛盾することはありません。

---

## 9. 価格差の表示

物件価格を `P`、相場価格帯を `[L, H]`（丸め後）とします。

| 判定 | 表示 |
| --- | --- |
| 割高 | 相場より `P − H` 万円 〜 `P − L` 万円ほど高い |
| 割安 | 相場より `L − P` 万円 〜 `H − P` 万円ほど安い |
| 相場通り | 差額は出さず「相場価格帯に収まっています」と表示 |

丸めの影響で割高／割安なのに差額が 0 になった場合は、差額の表示を省略します。

---

## 10. 駅徒歩分数

①以外のエリアで、最寄り駅から徒歩 10 分以上（10 分ちょうどを含む）の場合、
yield range の low / high の両方に +0.10 percentage point します。

エリア①は徒歩分数による補正をしません。
補正は `yield-master.json` を書き換えず、判定と相場価格計算の直前に適用します。

---

## 11. ユーザーに返さない情報

次はエンジンの内部レスポンスには含みますが、**公開 API のレスポンスには含めません**。

- 内部計算用の収益率（`yieldPercent`）
- 収益率の基準レンジ（`rateLow` / `rateHigh`）
- エリア判定用の内部コード（`areaCode`）とシートキー
- 判定の根拠となった行（`ageBracketLabel`）
- DB 上の内部 ID

管理画面では管理者に限り参照できます。
